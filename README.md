# Спринт 5

## Исходные данные

*Перенес некоторые факты из описания бизнеса, чтобы можно было ссылаться на них из заданий.*

### Категории пользователей

- **КП1.** Клиенты -- те, кто рассматривает приобретение жилья у компании.
- **КП2.** Собственники -- те, кто приобрёл жильё у компании.

### Продукты

*В описании бизнеса есть небольшое противоречие: онлайн-тур и онлайн-сделка представлены как отдельные приложения, хотя на схеме клиент взаимодействует только с витриной -- при выполнении заданий считал их частью витрины.*

- **ПР1.** Онлайн-витрина -- подбор и бронирование недвижимости. Используется клиентами. Включает два важных модуля:
  - **ПР1.1.** Онлайн-тур -- осмотр жилья без посещения объекта.
  - **ПР1.2.** Онлайн-сделка -- проведение сделки онлайн.
- **ПР2.** Мобильное приложение ЖКУ -- оплата ЖКУ, информация от УК, данные о ремонте, управление умным домом. Используется собственниками.

### Домены

*В описании бизнеса домен данных назван как "Дата" -- для исключения путаницы с календарной датой в заданиях использовал название "Данные". Также по описанию этот домен содержит некое приложение для BI, однако на схеме оно не отражено -- предположил, что BI-аналитик использует какое-то готовое решение, например Apache Superset.*

- **Д1.** Продажи -- онлайн-витрина, client-tour-app, client-mart-app, client-crm-app, client-mart-estate-app.
- **Д2.** ЖКУ -- мобильная витрина, tenant-core-app, CRM собственников.
- **Д3.** Финансы -- accountant-service-1, служба каталогов.
- **Д4.** Данные -- data warehouse, data lake (S3), BI (включает отчеты).

Д1 и Д2 совместно используют службу каталогов.

### Инфраструктура

Преимущественно собственные серверы: приватное облако + свой ЦОД + арендованные мощности облачного провайдера (могут быть использованы для временного расширения мощностей при доработке и тестировании). Резервное копирование всех БД. Доступ внешних пользователей возможен только через межсетевой экран.

### Команды

- **КМ1.** Продуктовая команда:
  - **КМ1.1.** Функциональная: владелец продукта, аналитики, разработчики, инженеры по эксплуатации, DevOps-инженер.
  - **КМ1.2.** Операционная: менеджеры.
- **КМ2.** ИБ: один специалист на компанию. Ему передают не все решения и изменения.

### Проблемы

- **П1.** Нарушен контроль данных: несколько точек регистрации клиентов без координации, несистемный контроль внутренних потоков, нет ограничений доступа в системах обработки данных.
- **П2.** Проблемы с API партнёров (управляющих компаний): нет единых политик безопасности, персональные данные в контрактах API, партнёр одной УК видит и меняет данные другой УК.

### Цели

- **Ц1.** Повысить удовлетворённость клиентов: в личном кабинете отображаются данные других клиентов.
- **Ц2.** Разблокировать обработку данных: запуск BI/ML/AI-продуктов упирается в управление и хранение потоков данных.
- **Ц3.** Реагировать на инциденты: утечка данных у конкурента, руководство обеспокоено.
- **Ц4.** Проверить соответствие законодательству РФ (152-ФЗ) и предотвратить штрафы.

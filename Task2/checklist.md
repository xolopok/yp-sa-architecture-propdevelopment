# PropDevelopment: проверочный лист безопасности для бизнес-систем

*Задание требует выбрать только нужные разделы листа и обосновать этот выбор, но не указывает, куда сохранить обоснование -- добавил как два отдельных раздела перед листом.*

## Включённые разделы проверочного листа

Сокращения описаны в [README.md](../README.md).

Включены разделы, которые закрывают обозначенные проблемы и цели.

- **I. Управление доступом** -- закрывает П1, П2, Ц1, Ц4.
  - П1: со стороны систем обработки данных нет ограничений на доступ (вопросы I.4, I.9, I.14), а несколько точек регистрации клиентов существуют без единого реестра учётных записей (вопросы I.11, I.12).
  - П2: партнёр одной УК может видеть и изменять данные другой УК -- нарушена авторизация, API партнёров работают без единых политик (вопросы I.4, I.7, I.14).
  - Ц1: чужие ФИО в личном кабинете указывают на отсутствие изоляции чувствительных данных (вопрос I.9).
  - Ц4: разграничение доступа -- базовое требование 152-ФЗ к защите персональных данных (вопросы I.6, I.9, I.13).
- **II. Безопасность данных** -- закрывает П1, П2, Ц1, Ц2, Ц4.
  - П1: внутренние потоки данных контролируются несистемно, сырые данные баз продаж и ЖКУ по CDC попадают в общее хранилище без ограничений -- отсутствуют классификация, мониторинг доступа и обезличивание (вопросы II.1, II.7, II.8, II.13).
  - П2: контракты API партнёров передают персональные данные без системного контроля -- нужны правила классификации и передачи данных (вопросы II.1, II.7, II.8).
  - Ц1: чужие ФИО в личном кабинете -- симптом отсутствия контроля целостности данных (вопрос II.11).
  - Ц2: блокировка BI/ML/AI-продуктов прямо названа следствием проблем с управлением потоками данных (вопрос II.9).
  - Ц4: учёт персональных данных, классификация и обезличивание -- прямые требования 152-ФЗ (вопросы II.1, II.7, II.13).
- **IV. Управление инцидентами** -- закрывает Ц3, Ц4.
  - Ц3: утечка у конкурента показала цену бездействия, а обнаруживать и расследовать инциденты нечем: SIEM, оповещения и план реагирования не описаны, специалист по ИБ один (вопросы IV.1-IV.3).
  - Ц4: 152-ФЗ обязывает уведомить Роскомнадзор об утечке персональных данных в течение 24 часов -- без процесса реагирования и учёта инцидентов это невыполнимо (вопросы IV.3, IV.5).

## Исключённые разделы проверочного листа

Исключены разделы, чьи объекты проверки не упоминаются ни в проблемах, ни в целях. Также исключены разделы, чьи вопросы перекрываются включёнными разделами.

- **III. Защита инфраструктуры** -- в проблемах и целях не фигурируют сетевые атаки, вредоносное ПО, DDoS, уязвимости ОС и приложений. Доступ внешних пользователей через межсетевой экран уже покрыт вопросом I.10, а проблемы API партнёров -- это авторизация и контроль данных, а не защита периметра. Риск утечки (Ц3) в кейсе связан с неконтролируемым доступом и потоками данных, а не с сетевыми атаками.
- **V.1. Общие вопросы** -- вопросы раздела касаются корпоративных устройств и удалённой работы (MDM, VPN, неавторизованные устройства), которых нет в описании. Мобильное приложение собственников -- клиентский продукт: связанные с ним риски проходят через API и уже покрыты разделами I и II. Резервное копирование (вопрос V.1.4) перекрывается вопросами II.4 и II.6; облачные мощности арендуются только временно для разработки и тестирования.
- **V.2. Управление оборудованием и физической безопасностью** -- физическая защита серверных и инвентаризация оборудования не упоминаются ни в проблемах, ни в целях. Безопасное удаление данных перед утилизацией оборудования (вопрос V.2.3) перекрывается вопросом II.10.
